# 19. 일정

24주, 8단계로 나눈다. 수집 경로부터 만들어 1단계 끝에 폭주 실험을 돌릴 수 있게 하고, 화면은 데이터가 쌓인 뒤에 붙인다. 시작일은 정하지 않았다.

| 단계 | 기간 | 범위 | 끝났다고 보는 기준 |
| --- | --- | --- | --- |
| 1. 골격과 수집 | 1주에서 3주 | 멀티 모듈, compose의 core 프로필, 봉투 형식, ingest, 한도 스크립트, loadgen, 기본 지표 | 폭주 부하에서 ingest가 응답하고 대기열이 상한에서 멈춤 |
| 2. 처리와 저장 | 4주에서 6주 | worker의 단계 구조, 지문 규칙, 두 저장소의 스키마, 건수 집계, 중복과 격리 | 보낸 건수와 집계 건수가 일치. 지문 사례 테스트 통과 |
| 3. 스프링 SDK와 콘솔 뼈대 | 7주에서 9주 | Starter SDK, 데모 앱, 로그인과 권한, 이슈 목록과 상세 | 데모 앱의 예외가 화면에 이슈로 보임. SDK 부담 측정 |
| 4. Vue SDK와 소스맵 | 10주에서 12주 | Vue SDK, 소스맵 업로드와 해석, 캐시, 릴리스와 재발 판정 | 압축된 번들의 에러가 원본 위치로 보임 |
| 5. 관측과 자원 실험 | 13주에서 15주 | obs 프로필, 대시보드 5개, 경보 규칙, 18.3의 자원 실험 | 실험 결과 표를 채우고 14장의 값을 확정 |
| 6. 성능 추적 | 16주에서 18주 | 전파, 계측, 표본 추출, 스팬 저장, 성능 화면 | 서비스 2개를 지나는 요청이 한 그림으로 보임 |
| 7. 업타임, 알림, 통합 화면 | 19주에서 21주 | 모니터와 판정, 알림 규칙과 억제, 전체 보기와 시스템 보기, 팬파라이브와 CoPage 연결 | 두 서비스의 에러와 요약 카드가 한 화면에 보임 |
| 8. 마무리 | 22주에서 24주 | 18.4의 장애 실험, 오라클 배포, 문서, 선택 과제(로컬 k3d) | 실험 문서 완성. 공개 주소에서 시연 가능 |

순서에 대한 판단은 세 가지다.

- **기본 지표는 1단계부터 넣는다.** 대시보드는 5단계에 만들지만, 대기열 길이와 응답 시간 같은 지표가 없으면 1단계의 폭주 실험을 판정할 수 없다.
- **콘솔 화면은 3단계에 시작한다.** 구현 전에 시안을 먼저 만들어 고르는 절차를 3단계 첫 주에 둔다.
- **팬파라이브와 CoPage 연결은 7단계다.** 그 전까지는 데모 앱으로 개발한다. 남의 서비스에 SDK를 붙이는 것은 SDK가 안정된 뒤에 한다. CoPage는 그때까지 협업 서버가 구현되어 있어야 붙일 수 있다.

단계를 작업 26개로 나눈 목록과 작업 하나를 진행하는 절차는 [WORKFLOW.md](./WORKFLOW.md)에 있다.
