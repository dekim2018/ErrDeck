# 18. 검증 계획

이 문서의 설계 값은 전부 가설이다. 검증은 네 가지로 한다. 테스트로 규칙의 정확성을, 부하 실험으로 2.2의 목표를, 자원 실험으로 14장의 값을, 장애 실험으로 격리와 복구를 확인한다. 결과 표는 실행한 뒤에만 채운다.

## 18.1 테스트

| 대상 | 방법 |
| --- | --- |
| 지문 규칙 | 6.3의 규칙마다 사례 테스트. 줄 번호, 프록시 번호, 람다 번호만 다른 스택 두 개가 같은 지문이 되는지, 다른 버그가 다른 지문이 되는지 |
| 소스맵 해석 | 실제 Vite 빌드 결과물로 위치 수백 개를 복원해 기존 라이브러리의 결과와 대조. VLQ 인코딩과 디코딩의 왕복 테스트 |
| 봉투 형식 | SDK와 worker가 같은 예제 파일을 공유. SDK가 만든 봉투를 worker가 해석하는 테스트를 양쪽 모듈의 빌드에서 실행 |
| 저장소 접근 | 실제 PostgreSQL, Redis, ClickHouse 컨테이너를 띄워 통합 테스트 |
| Lua 스크립트 | 한도 차감과 적재의 원자성. 동시에 여러 요청을 보내 한도를 넘는 건이 없는지 |
| SDK | 가짜 ingest를 상대로 큐 넘침, 거절 응답, 종료 시 비우기 |
| 콘솔 화면 | 컴포넌트 테스트와 접근성 검사 |

## 18.2 부하 실험

loadgen이 실제 SDK와 같은 봉투를 만들어 보낸다. 실험마다 환경(코어 수, 메모리, 커밋)을 함께 기록한다.

| 실험 | 부하 | 확인하는 것 |
| --- | --- | --- |
| 지속 부하 | 초당 500건, 30분, 지문 1,000종 | 대기열 나이가 늘지 않는가. 표시 지연 p95 |
| 폭주 | 같은 에러 초당 5,000건, 5분 | ingest의 p99. 보낸 건수와 집계 건수의 일치. 다른 프로젝트의 이벤트가 제때 처리되는가 |
| 지문 다양성 | 지문 10,000종을 고르게 | 캐시가 안 맞을 때의 PostgreSQL 부하 |
| 소스맵 첫 조회 | 새 릴리스의 브라우저 에러 1,000건을 동시에 | 해석이 한 번만 일어나는가. 힙 사용량 |
| 조회 간섭 | 폭주 중에 콘솔에서 30일 집계 조회 | 조회가 수집 응답 시간에 영향을 주는가 |
| SDK 부담 | 데모 앱에 요청 부하. SDK를 켠 것과 끈 것 | 요청 시간의 차이. 2.2의 목표 |

## 18.3 자원 실험

변수 하나만 바꾸고 나머지는 고정한다.

| 바꾸는 것 | 값 | 보는 것 |
| --- | --- | --- |
| worker 계산 풀 크기(CPU 상한 2.0 고정) | 1, 2, 4, 8 | 처리량, CPU 제한 구간 비율, 단계별 시간. 2보다 크게 잡으면 오히려 느려지는지 |
| worker의 GC | Parallel, G1, Serial | 처리량, 멈춤 시간 |
| ClickHouse 묶음 크기 | 500, 5,000, 50,000행 | 쓰기 시간, 활성 파트 수, 표시 지연 |
| ingest의 동시 호출 상한 | 있음, 없음. Redis에 지연 주입 | 힙 사용량, 응답 시간, 거절 수 |
| api의 커넥션 풀 | 4, 10, 30 | 처리량, 풀 대기 수, PostgreSQL CPU |
| 압축 객체 헤더 | 켬, 끔 | worker 힙 사용량 |
| 서버 코어 수 | 4, 2 | 17.4의 오라클 프로필에서 처리량이 얼마나 줄어드는가 |

첫째 실험이 14.2의 CPU 제한 현상을 직접 보여 준다. 스레드를 늘렸는데 처리량이 줄고 제한 구간 비율이 오르는 그래프가 나오면, 풀 크기를 코어 수에 맞춘 근거가 된다.

## 18.4 장애 실험

팬파라이브의 장애 실험 스크립트와 같은 형식으로 만든다.

| 실험 | 방법 | 기대하는 결과 |
| --- | --- | --- |
| worker 강제 종료 | 처리 중에 `docker kill` | 재시작 후 미확인 항목을 이어받음. 유실 0건. 중복 건수를 기록 |
| ClickHouse 정지 | 10분 동안 정지 | 어느 프로세스의 메모리도 계속 늘지 않음. ingest가 503 응답. 재개 후 자동 복구 |
| Redis 재시작 | 부하 중 재시작 | 잃은 건수가 마지막 1초 분량 이내 |
| PostgreSQL 정지 | 1분 동안 정지 | ingest는 키 캐시로 30초 동안 수신 유지. worker는 멈췄다가 재개 |
| 이 서비스 전체 정지 | 데모 앱에 부하를 건 채로 전부 내림 | 데모 앱의 요청 실패 0건. SDK 메모리가 늘지 않음 |
| worker 2대 | `--scale worker=2` 로 부하와 점검 실행 | 같은 모니터의 중복 점검 0건. 중복 알림 0건 |

## 18.5 결과 기록

결과는 저장소의 `docs/EXPERIMENTS.md` 에 실험별 표로 남긴다. 실행하지 않은 실험의 칸은 비워 둔다. 목표를 못 지킨 결과도 그대로 적고, 원인과 바꾼 설정을 함께 적는다. 설계 값이 처음과 달라진 이력이 이 프로젝트에서 가장 설명할 거리가 많은 부분이 된다.
