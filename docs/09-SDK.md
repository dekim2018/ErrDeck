# 11. SDK 설계

SDK의 첫째 규칙은 감시 대상에 해를 끼치지 않는 것이다. SDK는 남의 프로세스 안에서 돈다. 이 서비스가 느리거나 죽었을 때 SDK가 요청 스레드를 붙잡거나 메모리를 계속 쓰면, 모니터링 도구가 장애의 원인이 된다.

## 11.1 공통 규칙

| 규칙 | 구현 |
| --- | --- |
| 요청 스레드를 막지 않는다 | 요청 스레드는 길이가 정해진 큐에 넣기만 한다. 큐가 차면 기다리지 않고 버린다 |
| 메모리가 늘지 않는다 | 큐 길이 상한, 이벤트 크기 상한, 재시도 1회 |
| 예외를 밖으로 던지지 않는다 | SDK의 모든 진입점을 감싼다. SDK 내부 오류는 로그 한 줄로 끝낸다 |
| 거절을 따른다 | 429와 503의 Retry-After 동안 전송을 멈춘다 |
| 같은 에러를 접는다 | 같은 스택의 에러가 10초 안에 5건을 넘으면 이후는 횟수만 세고, 구간이 끝날 때 대표 1건에 횟수를 실어 보낸다 |
| 버린 것을 센다 | 사유별 건수를 client_report로 보낸다 |

## 11.2 Spring Boot Starter

의존성 하나와 설정 몇 줄로 붙는다.

```yaml
errdeck:
  dsn: https://{공개키}@{호스트}/{프로젝트ID}
  environment: production
  release: ${GIT_COMMIT:unknown}
  in-app-packages: com.livebroadcast
  traces:
    sample-rate: 0.1
```

**예외를 잡는 곳**

| 경로 | 방법 |
| --- | --- |
| 웹 요청 | 우선순위가 가장 높은 예외 리졸버가 예외를 요청 속성에 적어 두기만 하고 처리는 넘긴다. 서블릿 필터가 응답이 끝난 뒤 상태 코드가 500 이상일 때만 그 예외를 보낸다 |
| `@Scheduled`, `@Async` | 스케줄러의 오류 핸들러와 비동기 예외 핸들러 |
| 스트림 소비자와 이벤트 리스너 | 로그 어펜더. `log.error` 에 예외가 함께 넘어오면 보낸다 |
| 그 밖의 스레드 | 기본 미처리 예외 핸들러 |
| 직접 호출 | `ErrDeck.capture(e)` |

웹 요청을 리졸버와 필터 두 단계로 나눈 이유가 있다. 팬파라이브와 CoPage는 전역 예외 처리기로 예외를 응답으로 바꾼다. 그래서 대부분의 예외는 처리된 예외다. 처리되지 않은 것만 잡으면 거의 아무것도 안 잡히고, 전부 잡으면 잘못된 입력 같은 400번대 예외까지 이슈가 된다. 예외는 먼저 기억해 두고, 최종 상태 코드를 본 뒤 보낼지 정한다.

**전송 구조**

1. 요청 스레드가 예외 참조와 요청 정보(주소, 메서드, 사용자 ID, trace_id)의 사본을 묶어 큐에 넣는다. 큐 길이는 1,000이다.
2. 전송 전용 스레드 하나가 2초마다 또는 50건이 모이면 꺼낸다.
3. 스택트레이스를 JSON으로 바꾸고 압축하는 일은 전송 스레드에서 한다. 요청 스레드에는 이 비용이 없다.
4. JDK HttpClient로 보낸다. 제한 시간은 3초다.
5. 애플리케이션이 종료될 때 최대 2초 동안 큐를 비운다.

전송 스레드를 가상 스레드가 아닌 일반 데몬 스레드 하나로 둔 이유는 일의 절반이 직렬화와 압축, 즉 CPU 작업이기 때문이다. 하나로 고정하면 SDK가 쓰는 CPU가 코어 하나를 넘지 못한다.

**확인이 필요한 점**: 팬파라이브 저장소를 확인한 결과 gateway는 WebFlux 기반이다. 서블릿 필터와 리졸버가 동작하지 않으므로 gateway용 WebFilter 구현을 SDK에 따로 넣는다.

## 11.3 Vue SDK

```js
app.use(ErrDeck, {
  dsn: import.meta.env.VITE_ERRDECK_DSN,
  release: __RELEASE__,
  environment: import.meta.env.MODE,
  router,
  tracesSampleRate: 0.1,
})
```

| 항목 | 설계 |
| --- | --- |
| 에러를 잡는 곳 | `app.config.errorHandler`(컴포넌트 이름과 발생 위치 포함), `window.onerror`, `unhandledrejection` |
| 빵부스러기 | 라우트 이동, 클릭한 요소, API 호출의 주소와 상태 코드. 최근 50개만 유지 |
| 전송 | `fetch` 의 `keepalive` 옵션. 탭이 숨겨질 때는 `navigator.sendBeacon` 으로 남은 것을 보냄 |
| 압축 | 브라우저의 CompressionStream으로 gzip. 압축 여부는 쿼리 `enc=gzip` 으로 알림 |
| 릴리스 | Vite의 `define` 으로 빌드 때 커밋 해시를 넣음. 소스맵 업로드와 같은 값 |
| 크기 목표 | 압축 후 10KB 이하. 외부 의존성 없음 |

압축 여부를 헤더가 아니라 쿼리로 알리는 이유는 5.2와 같다. `Content-Encoding` 헤더를 붙이면 브라우저가 사전 요청을 보낸다.

탭이 닫힐 때 보내는 방식이 중요하다. 에러 직후 사용자가 페이지를 떠나는 일이 많은데, 일반 요청은 페이지가 사라지면 취소된다. `keepalive` 와 `sendBeacon` 은 페이지가 사라져도 전송이 끝까지 간다.

한계도 있다. 광고 차단 확장 프로그램이 수집 주소를 막을 수 있다. 이 경우 브라우저 에러는 일부 사용자에게서 오지 않는다.

## 11.4 감시 대상에 붙이는 작업

| 대상 | 작업 |
| --- | --- |
| 팬파라이브 스프링 서비스 5개 | starter 의존성 추가, 설정, Actuator의 프로메테우스 엔드포인트 열기(13장) |
| 팬파라이브 web | Vue SDK 추가, 빌드 설정을 숨은 소스맵으로 변경, 빌드 스크립트에 업로드 단계 추가 |
| CoPage app | 위의 스프링 작업과 같음. WebSocket 핸들러의 예외는 `ErrDeck.capture` 로 직접 보냄 |
| CoPage web | 위의 Vue 작업과 같음 |

SDK 패키지를 어디에 올릴지는 정하지 않았다. 20장의 미정 사항에 적는다.

## 11.5 측정할 값

SDK를 붙인 것과 안 붙인 것의 요청 시간 차이, SDK 큐의 최대 길이, 버린 건수, 감시 대상 힙 사용량의 차이, Vue SDK의 번들 크기를 잰다. 이 서비스를 꺼 둔 상태에서 감시 대상에 부하를 걸어 요청 실패가 0건인지 확인하는 실험이 가장 중요하다.

## 구현하면서 바뀐 점

- **에러와 트랜잭션은 다른 봉투로 보낸다**(03 작업): ingest는 본문을 풀지 않으므로 봉투의 종류를 쿼리로 알린다. 트랜잭션 봉투는 `?kind=tx` 를 붙이고, 에러와 client_report 봉투는 붙이지 않는다(5장 끝).
- **Spring Starter의 구현**(09 작업): 코드는 `sdk-spring` 에 있다. 의존성을 추가하고 `errdeck.dsn` 을 설정하면 켜지고, `errdeck.enabled=false` 로 끈다. 큐 길이, 묶음 크기, 간격, 제한 시간, 접기 구간과 기준도 `errdeck.*` 로 바꿀 수 있다. 감시 대상에 있는 것(서블릿, WebFlux, Logback)에만 붙는다.
- **WebFlux(gateway)**: `WebFilter` 가 처리되지 않고 올라온 서버 오류만 보낸다. 컨트롤러의 `@ExceptionHandler` 가 처리한 예외와 사용자 ID는 보내지 않는다. 이유는 `docs/CHOICES.md` 09-1, 09-2.
- **접기의 비교 기준**: 예외 클래스와 위쪽 20프레임(줄 번호 포함)을 요청 스레드에서 그대로 비교한다. 지문 규칙을 쓰지 않는다(CHOICES 09-3).
- **같은 예외 객체를 여러 경로가 잡아도 한 번만 보낸다**(CHOICES 09-4).
- **버린 이유**: client_report의 이유는 `queue_overflow`, `rate_limited`, `queue_full`, `too_large`, `network_error`, `unauthorized` 여섯 가지다.

그 밖에 이 작업에서 정한 것은 [CHOICES.md](./CHOICES.md)의 09 절에 있다.
- **Vue SDK의 구현**(14 작업): 코드는 `sdk-vue`(npm 패키지, 실행 의존성 없음, vue 는 peer)에 있다. `createErrDeck({ dsn, release, environment, router })` 를 `app.use` 로 붙인다. 번들은 9.6KB, gzip 3.8KB 다(목표 10KB 이하).
- **압축하지 않은 봉투**: 탭을 떠날 때 `sendBeacon` 으로 보내는 봉투는 압축하지 않는다. worker 가 gzip 머리로 가린다(CHOICES 14-1).
- **요청 정보**: 쿼리와 조각을 보내지 않는다(CHOICES 14-2). 앱 프레임 판정은 하지 않는다(14-3).
- **확인**(커밋 464078d): 압축된 데모 화면(`vite preview`)에서 버튼 네 개를 누르자 봉투 하나가 POST 한 번(202)으로 갔고 OPTIONS 는 없었다. 이어서 탭을 떠나며 sendBeacon 으로 한 건을 더 보냈다. 다섯 건 모두 ClickHouse 에 저장되었고 격리는 없었다.
