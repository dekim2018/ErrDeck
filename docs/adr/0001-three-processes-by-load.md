# ADR 0001. 프로세스를 부하 성격으로 셋으로 나눈다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [02-ARCHITECTURE.md](../02-ARCHITECTURE.md) (4.2)

## 고른 것

한 저장소의 코드를 ingest(수집), worker(처리), api(조회) 세 프로세스로 띄운다. 세 프로세스는 서로 직접 호출하지 않고 대기열과 저장소로만 이어진다.

## 버린 대안

프로세스 하나에 전부 넣기. 도메인별 MSA(프로젝트 서비스, 이슈 서비스, 알림 서비스)

## 이유

- 수집은 짧은 I/O가 아주 많고, 처리는 CPU를 많이 쓰고, 조회는 건수는 적지만 한 건이 무겁다. 한 프로세스에 두면 서로를 굶긴다.
- 에러 폭주 때 worker가 CPU를 전부 써도 ingest는 따로 응답한다.
- 프로세스마다 CPU와 메모리 상한, 스레드 풀, GC를 역할에 맞게 다르게 줄 수 있다.
- 이 서비스의 병목은 도메인 경계가 아니라 수집과 처리의 부하 차이에 있다. 도메인별로 나누면 서비스 간 호출만 늘어난다.

## 감수하는 것

- 프로세스가 셋이라 배포와 설정 파일이 늘어난다.
- 같은 도메인 코드를 공유하므로 스키마를 바꿀 때 세 프로세스를 함께 올려야 한다.

## 측정할 값

폭주 부하에서 ingest의 응답 시간(p99), 폭주 중 api 조회가 ingest에 주는 영향

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
