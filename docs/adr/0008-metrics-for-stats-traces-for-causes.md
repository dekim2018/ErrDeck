# ADR 0008. 성능 통계는 프로메테우스, 원인 분석은 표본 추적으로 나눈다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [06-TRACING.md](../06-TRACING.md) (8.1)

## 고른 것

엔드포인트의 p95, 처리량, 에러율은 감시 대상이 내보내는 요청 시간 히스토그램으로 프로메테우스가 계산한다. ErrDeck은 표본 요청의 스팬만 저장해 어디서 시간을 썼는지 보여 준다.

## 버린 대안

전체 요청의 스팬 저장. 표본으로 p95 계산. 서버에서 추적 전체를 받은 뒤 고르기. OpenTelemetry 에이전트 사용

## 이유

- 전체 저장은 저장량과 수집 부하가 요청 수에 비례한다.
- 표본으로 계산한 통계는 비율에 따라 흔들리고 드문 엔드포인트는 표본이 없다.
- 히스토그램은 모든 요청을 세지만 크기가 요청 수와 무관하다.

## 감수하는 것

- 성능 화면이 두 출처(프로메테우스, ClickHouse)를 합쳐야 한다.
- 시작할 때 뽑히지 않은 요청이 느리거나 에러가 나면 그 서비스의 구간만 남는다(부분 추적).

## 측정할 값

추적을 켠 것과 끈 것의 요청 시간 차이, 트랜잭션당 평균 스팬 수

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
