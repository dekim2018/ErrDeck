# ADR 0003. ingest는 본문을 해석하지 않고 Redis 왕복 한 번으로 끝낸다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [03-INGEST.md](../03-INGEST.md) (5.4)

## 고른 것

ingest는 크기, 키, 출처만 확인하고 압축된 본문을 그대로 대기열에 넣는다. 한도 차감, 대기열 길이 확인, 적재를 Lua 스크립트 하나로 묶는다.

## 버린 대안

ingest에서 압축을 풀어 내용 검증. 프로젝트마다 대기열 하나. 로컬 디스크에 쓰고 worker가 읽기

## 이유

- 압축 해제와 JSON 해석은 CPU 작업이다. 폭주 때 이 일이 ingest로 몰리면 응답이 느려지고 SDK의 재시도가 겹친다.
- 스크립트 하나로 묶으면 왕복이 한 번이고, 확인과 적재 사이에 다른 요청이 끼어들지 못한다.
- 프로젝트별 공정성은 프로젝트 한도로 이미 확보한다.

## 감수하는 것

- 형식이 틀린 봉투도 대기열까지 들어온다. worker가 압축을 풀 때 출력 크기 상한을 걸고, 해석에 실패한 것은 격리한다.

## 측정할 값

ingest 응답 시간(p50, p99), 응답 코드별 건수, Lua 스크립트 실행 시간

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
