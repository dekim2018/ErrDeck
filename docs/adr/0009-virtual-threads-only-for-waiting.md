# ADR 0009. 가상 스레드는 기다리는 일에만 쓰고 상한을 직접 만든다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [12-RESOURCES.md](../12-RESOURCES.md) (14.4)

## 고른 것

ingest의 요청, 업타임 점검, 알림 발송, api의 조회는 가상 스레드로 처리한다. 압축 해제, 소스맵 해석, 지문 계산은 크기가 코어 수와 같은 일반 스레드 고정 풀로 처리한다. 가상 스레드가 부르는 외부 호출은 세마포어로 동시 수를 제한한다.

## 버린 대안

모든 일을 가상 스레드로. 공용 포크조인 풀과 병렬 스트림. 큰 스레드 풀 하나를 여러 용도로 공유

## 이유

- 가상 스레드는 기다리는 동안 실행 스레드를 내놓는다. 계산만 하는 가상 스레드는 끝날 때까지 실행 스레드를 붙잡으므로 이득이 없다.
- 톰캣의 스레드 풀 200개는 뒤쪽으로 가는 동시 호출의 천장이기도 했다. 가상 스레드로 바꾸면 이 천장이 사라진다.
- CPU를 쓰는 스레드 수가 컨테이너의 CPU 상한보다 많으면 할당량을 일찍 다 쓰고 프로세스 전체가 멈춘다.

## 감수하는 것

- 세마포어 크기라는 조정할 값이 늘어난다.
- 자리가 없으면 기다리지 않고 거절하므로 순간적인 거절이 생길 수 있다.

## 측정할 값

계산 풀 크기를 바꿔 가며 잰 처리량과 CPU 제한 구간 비율, Redis 지연을 주입했을 때 ingest의 힙 사용량

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
