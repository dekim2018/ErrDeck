# ADR 0005. 이벤트는 ClickHouse, 이슈는 PostgreSQL에 둔다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [01-PLAN.md](../01-PLAN.md), [08-DATA-MODEL.md](../08-DATA-MODEL.md) (3.3, 10장)

## 고른 것

수정되지 않는 대량 기록(이벤트, 트랜잭션, 점검 결과)은 ClickHouse에, 상태가 바뀌는 메타데이터(이슈, 프로젝트, 릴리스, 모니터)는 PostgreSQL에 둔다.

## 버린 대안

전부 PostgreSQL. 전부 ClickHouse

## 이유

- 이벤트는 건수가 많고 기간과 조건으로 집계해서 읽는다. 이슈는 건수가 적고 한 건씩 정확하게 읽고 쓴다.
- PostgreSQL에 이벤트를 쌓으면 30일 치를 지우는 작업과 집계 쿼리가 부담이 된다. ClickHouse는 날짜 파티션을 통째로 버린다.
- ClickHouse는 행 단위 수정과 트랜잭션이 맞지 않는다.

## 감수하는 것

- 두 저장소에 걸친 쓰기는 하나의 트랜잭션으로 묶이지 않는다. 화면은 두 곳의 결과를 합쳐서 보여 준다.

## 측정할 값

30일 치 디스크 사용량, 이슈 목록과 상세 화면의 쿼리 시간

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
