# ADR 0002. 대기열은 길이 상한이 있는 Redis Streams를 쓴다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [02-ARCHITECTURE.md](../02-ARCHITECTURE.md), [03-INGEST.md](../03-INGEST.md) (4.5, 5.5)

## 고른 것

ingest와 worker 사이에 Redis Streams를 둔다. 에러와 트랜잭션은 스트림을 따로 쓰고, 스트림마다 길이 상한을 둔다. Redis는 메모리가 차면 지우지 않고 쓰기를 거절한다.

## 버린 대안

Kafka. PostgreSQL 테이블을 대기열로 쓰기. ingest가 ClickHouse에 바로 쓰기

## 이유

- Kafka는 서버 1대의 메모리 예산에서 차지하는 몫이 크다. Redis는 한도와 캐시 때문에 이미 쓴다.
- PostgreSQL 테이블은 폭주 때 삽입과 삭제가 몰려 죽은 행과 WAL이 빠르게 늘고, 이슈 조회와 같은 DB를 건드린다.
- 소스맵 복원과 지문 계산이 저장 전에 끝나야 하므로 ingest가 ClickHouse에 바로 쓸 수 없다.
- 트랜잭션은 건수가 훨씬 많다. 한 스트림에 섞으면 에러가 트랜잭션 뒤에 줄을 선다.

## 감수하는 것

- Redis가 갑자기 죽으면 대기열의 마지막 1초 분량을 잃을 수 있다(AOF everysec).
- 대기열 접근은 포트 뒤에 두어 나중에 교체할 수 있게 한다.

## 측정할 값

봉투의 평균 크기와 스트림 메모리 사용량, 지속 부하에서 대기열의 가장 오래된 항목의 나이

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
