# ADR 0013. 배포는 compose를 기준으로 하고 쿠버네티스는 선택 과제로 둔다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [15-DEPLOY.md](../15-DEPLOY.md) (17.1, 17.2)

## 고른 것

로컬 docker compose를 기준 환경으로 삼고, 덮어쓰기 파일 하나로 오라클 무료 서버에 올린다. 컨테이너마다 CPU와 메모리 상한을 명시한다. 쿠버네티스는 마지막 단계의 선택 과제이고 한다면 로컬에서만 한다.

## 버린 대안

처음부터 쿠버네티스(k3s)

## 이유

- CPU 배분, 스레드 풀, 메모리 예산이라는 고민은 자원이 고정된 서버 1대에서 가장 선명하게 드러난다.
- 서버가 한 대면 배치할 곳이 없고 자동 복구는 재시작 정책으로 충분하다.
- worker 여러 대의 안전성, 강제 종료 후 복구, 자원 상한의 효과는 compose로도 확인할 수 있다.
- 컨테이너별 상한을 적어 두면 나중에 requests와 limits로 그대로 옮겨진다.

## 감수하는 것

- 무중단 교체 배포와 자동 확장은 기본 범위에서 보여 주지 못한다.
- 서버 전체가 죽는 경우는 대응하지 못한다.

## 측정할 값

4코어와 2코어에서의 처리량 차이

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
