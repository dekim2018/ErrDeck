# ADR 0006. 이벤트에 issue_id를 넣지 않고 지문으로 잇는다

- 상태: 확정
- 결정일: 2026-11-23
- 관련 문서: [04-PIPELINE.md](../04-PIPELINE.md) (6.4)

## 고른 것

ClickHouse의 이벤트에는 지문만 넣는다. 지문과 이슈의 대응은 PostgreSQL의 issue_fingerprints가 가진다. 이슈 하나가 지문 여러 개를 가질 수 있다.

## 버린 대안

이벤트에 issue_id 저장

## 이유

- 이슈를 병합하거나 분리할 때 지문 행의 issue_id만 바꾼다. ClickHouse의 이벤트는 건드리지 않는다.
- 지문 규칙을 고칠 때 전환 기간 동안 옛 지문과 새 지문을 같은 이슈에 함께 연결할 수 있다.
- 소스맵 없이 묶인 이슈를 나중에 제대로 복원된 이슈와 합치는 비용이 작다.

## 감수하는 것

- 이슈의 이벤트를 읽을 때 지문 목록을 먼저 알아야 한다.
- 병합이 많이 쌓인 이슈는 조회 조건의 지문 수가 늘어난다.

## 측정할 값

지문을 여러 개 가진 이슈의 조회 시간

## 다시 검토할 조건

부하 실험과 장애 실험 결과가 이 결정의 전제와 다르게 나오면 이 문서를 고치고 상태를 "대체됨"으로 바꾼다.
